## Hypotheses
1. [OPEN] tie badge rules require all matched criteria to equal the raw max, but scores above 200 exceed the intended 100-200 band.
2. [OPEN] score summary includes zeros or missing criteria in the matching set, causing grouped badges to select the wrong range.
3. [OPEN] UI renders badges from stale/generated data rather than the model output.

## Findings
- RED: `npm run test -- src/entities/badge/model/badge-model.test.ts` failed because unlocked IDs were only `spec_multi_high`, missing `spec_dd_high`.
- Root cause: criterion-specific badges used the active/highest-unique condition for unlock, so ties prevented collecting the individual criterion badges.
- GREEN: after separating `unlocked` from `isActive`, the targeted Vitest file passed with 3 tests.

## Final fix
- `frontend/src/entities/badge/model/badge-seeds.ts`: criterion badge unlock now checks its own criterion score band; active state keeps the highest/tie rules.
